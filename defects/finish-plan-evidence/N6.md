# N6 — Retryable window/hour blocks + honest skip-texted filter

Tranche: N6 (added 2026-09-30 by Major). Builder session, read-only against live systems.
No docker, no sends, no push, no crontab, no DB writes were performed in this session.

## Problem (observed live, Ford tranche 4)
4 blocks `rate-cap-exceeded` (per-HOUR cap 60/60) and 51 blocks `outside-business-hours`
(the 21:00 CT cutoff arrived mid-run). The 51 left `automation_runs` rows (status skipped)
and every block/failure left an outbound `messages` row with `adapter_status`
blocked/failed, which `--skip-texted-since` (`hasOutboundSmsSince`) then counted as a real
text. Major cleaned both by hand.

## What changed (smallest coherent change)

1. **`outside-business-hours` is now a RETRYABLE block** (N6.1) —
   `src/server/catchup-send.ts`. Added `WINDOW_CLOSED_RULE = 'outside-business-hours'` and a
   `RETRYABLE_BLOCK_RULES` set `{ rate-cap-exceeded, outside-business-hours }`. `isRetryable`
   now deletes the ledger row for either rule (and for `failed`), so a window-closed block no
   longer strands the recipient as "already followed up". Terminal blocks
   (opt-out/DNC/consent/invalid/blacklist) keep their row and stay final/counted. `remaining`
   now also counts window-closed blocks as still-owed.

2. **Clean stop before a doomed send** (N6.2) — `runCatchupSends` takes optional
   `perHour` (default wired to 60, matching `comms-rate-limiter`) and `windowCloseMs`, plus
   an injectable `now()` clock. Before each attempt it STOPS the run cleanly
   (`"<kind> — N remaining, re-run later"`, surfaced via `summary.stoppedReason`) when the
   per-hour SMS cap is already reached (rolling 60-min count of successful sends) or the A2P
   window has closed (`now() >= windowCloseMs`) — instead of firing sends the gate will only
   reject. Un-attempted recipients are counted in `remaining`. The window-close instant is
   derived centrally: `send-windows.ts` `windowState` now returns `nextCloseMs`
   (current open window's end), surfaced through `gatherFollowupCandidates` as
   `windowCloseMs`, and the script passes it (null when `--ignore-window`).

3. **Honest `--skip-texted-since`** (N6.3) — `src/server/messaging-hub-store.ts`
   `hasOutboundSmsSince` now IGNORES outbound rows whose `metadata.adapter_status` is
   `blocked` or `failed` (both the SQLite `json_extract` query and the in-memory fallback).
   Only delivered/sent — or status-less legacy/reply-path — outbound counts as "texted", so a
   customer whose only outbound row was a blocked/failed send is no longer wrongly skipped.

No other caller of `hasOutboundSmsSince` or the send loop changed behaviour; no new
followups were surfaced this tranche.
