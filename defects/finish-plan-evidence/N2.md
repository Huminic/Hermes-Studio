# N2 — Report email redesign + the other three deliveries + intro text

Builder evidence for NIGHT TRANCHE 2 (N2.1–N2.5). Context: N1 deployed at
`main@984884c7f`; Duane rejected the N1 daily email ("a list, not a report").
His manifest is FOUR deliveries per store per day + a one-time intro text.
Everything is DRY-RUN by default. No docker, no sends, no push, no crontab.

## What was built

- **N2.1** `src/server/report-email.ts` — `renderReportEmail(...)`, the single
  email-safe report template (light card on grey, wordmark + store name, bold
  headline, greeting + agent-voice context, 2×2 KPI tiles with colored dots +
  deltas, identity/stats section rows, optional table section, one green CTA,
  plain-text alternative). `renderDailyManagementEmail` rewritten on it (subject
  unchanged; omission footnote now appears ONCE — the N1 duplicate is fixed).
  `comms-preview.ts` enriches each alert bucket with `{leadId, firstName, source,
  createdUtc, leadStatus, leadType}` (read-only; names resolved via the capped
  `resolveLeadNames`) so "Needs attention" rows carry identities, not bare ids.
- **N2.2** `scripts/send-lead-source-report.ts` + `renderLeadSourceEmail` — tiles
  (leads 24h/7d/30d, sold 24h), top-10 source rows + overflow table, legacy-id
  footnote. Reads `<profile>-lead-source.json` (+ `raw-counts.json` for exact
  window totals).
- **N2.3** `--window wrapup` in `scripts/comms-preview.ts` (report-day 08:00 →
  now, `<profile>-wrapup-` file prefix; emits inbound-sms replies + sold/lost
  cohort). `scripts/send-daily-wrapup.ts` + `renderWrapupEmail` — tiles (leads
  today+delta, AI texts, replies received, needs attention), today's-leads-by-
  source rows, needs-attention rows, sold/lost cohort row.
- **N2.4** `scripts/send-text-report.ts` — texts `<profile>-text-report.txt`
  (`-wrapup` variant with `--window wrapup`) via `dispatchOutbound` (CommGate +
  pre-launch lock + comms_log, `bypassBusinessHours:false`), one message per
  recipient. Dry-run by default; `--send` refused when `--to` empty.
- **N2.5** `scripts/send-intro-text.ts` — the exact approved one-time intro copy
  from the store agent (Georgia for Ford / Caroline otherwise, or
  `comms.agent_name` when set). Same shared `blastSms` sender core as N2.4.

Shared: `scripts/sms-report-sender.ts` (`blastSms` + the dispatchOutbound-backed
default sender), reused by N2.4 + N2.5.

## Notes / carried decisions (truth-over-compliance)

- **Deltas.** Tiles show real numbers. The New-leads / Leads-today delta is
  derived from the clean 24h-vs-prior-24h lead pull in `raw-counts.json`; when
  that pair is absent the delta is omitted (never invented). AI-texts and
  replies tiles carry no delta (no prior-period value is stored) rather than a
  guessed one.
- **CTA URL.** "Open VinSolutions" links to the store-agnostic app home
  `https://apps.vinsolutions.com/` (no per-store CRM URL exists in studio
  config). If a per-store URL is later added to config, the `cta` field already
  accepts it.
- **`comms.agent_name`.** Not in the zod `CommsSchema`, so it is read
  defensively in `send-intro-text.ts` and preferred over the profile default
  when present; otherwise the flag / profile default applies.
- **Needs-attention names.** `resolveLeadNames` is capped (default 10 unique
  contacts); leads beyond the cap render as `Lead <id>` (never a fabricated
  name). `leadType` was added to the enriched alert detail (the plan's field
  list did not include it) because the row's "type" stat needs it.

## N2.6 — Design fixes from Duane's review (2026-09-26)

Applied to `src/server/report-email.ts` + `src/server/lead-notifications.ts`
(all three emails: morning / noon / wrap-up).

1. **Header.** The HUMINIC wordmark now sits centered on the white card with NO
   box or background behind it. Directly under it, a full-width gradient banner —
   mostly deep purple (`#4c1d95`) blending into fuchsia (`#c026d3`) toward the
   right corner via `linear-gradient`, with a `bgcolor="#4c1d95"` fallback for
   Outlook — holds the store name, the report headline and the one-sentence
   story, all in white. Tiles start below the banner. (No hosted transparent
   Huminic logo exists in the codebase / BRAND_* constants, so the centered
   wordmark is used per the plan's fallback.)
2. **Tables.** "Needs attention" and "AI coverage" are now real tables (extended
   `TableSection` with colored column headers + optionally colored cells, per-
   column alignment). Needs attention columns: Lead · Source · Waiting · Status ·
   Type. AI coverage columns: Agent · After-hours leads · Avg reply · Day texts ·
   Active 30d. No per-cell dot labels.
3. **One status scheme** (`STATUS_AMBER/RED/BLUE/GREY` + `waitingColor()` /
   `statusColor()` in report-email.ts, used everywhere): waiting = amber under
   24h, red at 24h or more; status New = blue; lead types grey. Tile dots use the
   same palette (New leads blue, Needs attention red, etc.).
